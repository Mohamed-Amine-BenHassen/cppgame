How a fight works

Save is
your sword.

A guardian's hit points are the number of trials on its floor. There is no clicking, no multiple choice. The compiler is the referee, and it does not care how confident you are.

Some trials pass.
That much damage.

You're shown the first line where your output parted ways with what was wanted - yours, then the guardian's. Character for character. Spacing counts.

a hit! 2 more trial(s) pass.
line 4 yours: hero hits for 7. goblin hp 15
line 4 wants: hero hits for 7, goblin hp 15

It doesn't compile?
Shielded.

No damage. You get the first compiler error, and only the first - the one that actually matters.

Right output,
wrong shape.

Floor 12 wants a real std::vector<Monster>. Floor 20 forbids delete. Faking the output earns nothing.

Seeded dice.

Everyone rolls the same numbers. That's how a combat log can be graded - and why your bugs reproduce.

A real compiler. Real tests.

Visual Studio's compiler on the desktop, clang compiled to WebAssembly on the tablet. Nothing is simulated, so nothing you learn here is a toy.

Two editions · one tower

Your desk,
or a plane.

Both versions read the same twenty-five floors from the same folder. Nothing is copied by hand, so they can't drift apart.

Desktop · Windows

A terminal, and your own editor.

Run one command. The game opens each floor's file for you, watches it, and strikes the moment you save.

  • Finds Visual Studio's compiler by itself
  • Write in whatever editor you already use
  • Arrow keys to walk the tower, Enter to fight
Tablet · any browser

The compiler runs inside the page.

clang and lld, built for WebAssembly and cached once. After that: no server, no install, no network.

  • Installs to the home screen as an app
  • A symbol row for { } ; << and friends
  • Autocorrect off - it would "fix" your identifiers
